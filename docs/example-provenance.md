## 分配示例 v2

此前分配示例未充分记录矩阵的生成过程与来源，却使用了自创、公有领域风格等容易造成误解的描述。新版改为由下述明确算式生成的固定实例；这是一项来源纠正，不推断旧数据的实际复制过程或法律状态。历史运行记录中的成本 14/13 属于旧实例，保留历史，不适用于新版。

生成入口是 `src/contestflow/examples.py` 的 `assignment_fixture()`，仅使用整数运算：

1. 初始状态（seed）为 `20260929`。
2. 重复 16 次：`state = (1664525 * state + 1013904223) mod 2**32`，然后取 `cost = 1 + state mod 30`。
3. 按行填入 4×4 矩阵，每个成本取值范围为闭区间 `[1, 30]`。

这是显式固定的算术配方，不声称高质量随机抽样或新的伪随机算法。本实例用于说明贪心方案可能劣于精确解，不据它推断总体优势。

```text
 7  16  25   8
17  30  17  20
17  24   9  26
13  10  15  18
```

逐行选择当前可用任务中最低成本（平手取较小列号）的基线成本为 **66**，列号序列为 `[0, 2, 1, 3]`。枚举全部 24 个排列得到最优成本 **44**，对应 `[3, 0, 2, 1]`；SciPy 的 `linear_sum_assignment` 须与枚举核对一致。这里均为从 0 开始的列号。以上数值只属于这一固定教学实例，不是性能基准或竞赛结果。

`{"costs": 矩阵}` 按 Python `json.dumps(data, sort_keys=True, ensure_ascii=False, allow_nan=False)` 编码为 UTF-8（默认空格、无末尾换行）后，SHA-256 为：

```text
f517d04a19ce133a5673a051ff32d03d564ee22a56161dff77fc6147f5d08129
```

新建示例时，`data/processed/provenance.json` 同时保存此规范数据哈希、实际 `input.json` 文件字节哈希、seed、配方及取值范围。实际文件使用缩进和末尾换行，所以文件字节哈希与规范数据哈希是两个不同口径。复现说明及候选论文写明配方和 AI 辅助，不把软件许可视为未知第三方材料的来源证明。

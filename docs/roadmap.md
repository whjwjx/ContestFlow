# 路线图与验证状态

ContestFlow 当前为 `0.2.0a1` Alpha：核心流程已经可运行，下一阶段重点是真实团队试用和减少具体赛题中的摩擦，而不是继续扩张通用功能。

## 当前具备

- 团队主导、Agent 主动执行的阶段闭环：规划、执行、验证、复盘、继续；
- 题面与附件索引、来源哈希、逐问要求和团队决策记录；
- 可复现实验、失败保留、指标底表和上游变更失效；
- 科研图表候选、HTML/PDF 构建、实际 ZIP 核验和字节冻结；
- 非默认目录工具发现、可复用工具与配色、功能预检和合成演练；
- 精确比赛仓库身份、里程碑提交和简单队友任务分支协作；
- 自包含 Agent skill、跨平台 CI 配置和 wheel/sdist 内容检查。

## 已验证范围

当前代码在 Windows / Python 3.13 完成全量回归、Ruff、skill 格式、教学例、HTML/PDF 合成预演、实际 ZIP 复现、wheel/sdist 构建与内容检查。Git 集成覆盖精确仓库根、父仓库拒绝、隐私目录忽略、任务分支推送和实验记录溯源。

公开仓库的 CI 另覆盖 Ubuntu/Windows × Python 3.11/3.13；实际通过状态以对应提交的 Actions 结果为准。PDF 引擎和字体未装入 CI，因此不能由 CI 推导完整 PDF 跨平台支持。

## 已知边界

- 真实团队尚需在新赛题中检验阶段粒度、读题包、分支协作和复盘是否顺手；
- CLI 不调用模型，也不提供后台无人值守 Agent、比赛平台上传或人工签认系统；
- 运行器不是 OS 沙箱；PDF、字体和第三方评测器仍需可信来源或独立隔离环境；
- 内置图表聚焦标量指标对比，分布、消融、配对和灵敏度图需按题目扩展；
- 当前不通用管理跨调用总费用、集群资源、R/MATLAB、专用求解器或远程服务；
- 自动检查不能证明数学推导、数据质量、引用真实性、匿名性、团队理解或比赛合规；
- 托管平台权限、分支保护、私密漏洞报告入口和仓库可见性由维护者在平台核对。

## 后续优先级

1. 用有权使用的真实赛题完成一次团队试用，记录 Agent 停滞、重复询问、证据断链和交接冲突。
2. 根据真实问题改进阶段计划、预算/停止条件和题型适配器；不为假想需求增加抽象层。
3. 补充高价值图表与证据契约，优先覆盖分布、消融、配对和灵敏度分析。
4. 仅在有明确需求时增加模型服务或更多工具集成，并先定义凭据、费用、隔离和停止条件。
5. 独立团队试用和公开反馈稳定后，再评估 `0.2` 稳定版。

发布步骤与维护者核对项见 [Alpha 发布检查](releasing.md)。历史实现与验证细节保留在 Git 提交中，不在本文件重复维护。
